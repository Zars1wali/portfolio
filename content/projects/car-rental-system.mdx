This was a **real collaborative project**: two developers, two GitHub accounts, real branch merges, pull requests, and code review comments. Not a solo upload.

## The OOP Design in Code

```cpp
// Abstract base — pure virtual interface enforces role contracts
class Person {
protected:
    string username;
    string password;
    string name;
    string contactNumber;
public:
    virtual void showProfile() = 0;       // pure virtual
    virtual void mainMenu() = 0;          // pure virtual
    string getUsername() { return username; }
    virtual ~Person() {}
};

// Customer — booking, history, feedback
class Customer : public Person {
private:
    vector<RentalRecord> rentalHistory;
public:
    void showProfile() override;
    void mainMenu() override;
    void rentVehicle(Vehicle& v, int days);
    void returnVehicle(string plateNum);
    void viewReceipt(string rentalId);
    void submitFeedback(int rating, string comment);
};

// Polymorphic vehicle hierarchy
class Vehicle {
protected:
    string plateNumber;
    string model;
    string brand;
    bool isAvailable;
    double dailyRate;
public:
    virtual double calculateRent(int days) = 0;  // pure virtual — each type implements differently
    virtual void display() = 0;
    string getPlate() { return plateNumber; }
    bool available() { return isAvailable; }
};

class Car : public Vehicle {
public:
    double calculateRent(int days) override {
        return dailyRate * days;   // base rate
    }
    void display() override;
};

class SUV : public Vehicle {
    bool hasRoofRack;
public:
    double calculateRent(int days) override {
        return dailyRate * days * (hasRoofRack ? 1.15 : 1.0);  // +15% for roof rack
    }
    void display() override;
};
```

**Why pure virtual instead of virtual with a default?** Forcing subclasses to implement `calculateRent()` prevents a new vehicle type (e.g., `ElectricVan`) from accidentally inheriting a wrong billing formula. The compiler enforces the contract.

## Features

### Authentication & Security
- User registration with unique username validation
- Password hashing (XOR + shift cipher) stored in `users.dat`
- Password recovery via registered security questions
- Session management with role-based menu routing

### Fleet Management (Admin)
- Add, update, remove vehicles (Car/SUV/Truck polymorphic types)
- Real-time availability tracking using `map<string, Vehicle*>`
- Fleet utilization reports — daily/weekly revenue summaries

### Rental Workflow (Customer)
- Browse available vehicles by type, price range, or model
- Rent with date validation and conflict checking
- Return processing with damage assessment prompt
- Receipt generation — itemized bill with `dailyRate × days + tax`

### Flat-file Persistence

All data persists across sessions through `fstream` binary files:

```text
users.dat    ── Customer and admin credentials (password-hashed)
vehicles.dat ── Full fleet inventory with availability status
rentals.dat  ── Active and historical rental records
feedback.dat ── Customer ratings and comments
```

No database — deliberately. This demonstrates understanding of serialization, file I/O patterns, and struct binary layout in C++, which would be replaced by a RDBMS in a production version.

### Billing Engine
- Auto-calculates total cost on return: `dailyRate × days`
- Late return penalty: **1.5× daily rate per overdue day**
- Generates formatted text receipt to console + appends to `receipts.log`
