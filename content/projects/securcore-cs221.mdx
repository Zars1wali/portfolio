## Project Overview

**SecurCore** is an advanced password manager and security analytics system developed as the capstone project for **CS221 — Data Structures and Algorithms** at the university, instructed by **Dr. Zubair Ahmed**. Built entirely in **C++17**, it demonstrates practical applications of core data structures in a real-world cybersecurity context.

## Data Structures Used

The project was designed to showcase DSA concepts in a non-trivial application:

```cpp
// AVL Tree node — used for O(log n) sorted password retrieval
struct AVLNode {
    string key;      // site domain
    string password; // encrypted vault entry
    int height;
    AVLNode* left;
    AVLNode* right;

    AVLNode(string k, string p)
        : key(k), password(p), height(1),
          left(nullptr), right(nullptr) {}
};

// Self-balancing insert with rotation
AVLNode* insert(AVLNode* node, string key, string pass) {
    if (!node) return new AVLNode(key, pass);
    if (key < node->key)
        node->left = insert(node->left, key, pass);
    else if (key > node->key)
        node->right = insert(node->right, key, pass);
    else return node; // duplicate site

    node->height = 1 + max(height(node->left),
                           height(node->right));
    return rebalance(node);
}

// Hash map for O(1) credential lookup
unordered_map<string, string> vaultIndex;

// Graph adjacency list for breach propagation analysis
unordered_map<string, vector<string>> siteGraph;

// Stack-based undo history for vault edits
stack<VaultAction> undoStack;
```

## Core Features & Architecture

### 🔐 Password Vault (AVL Tree)
Passwords are stored in an **AVL tree** keyed by site domain, ensuring O(log n) insert, lookup, and deletion with guaranteed balance. The tree is serialized to an encrypted flat file for persistence.

### ⚡ Fast Lookup Index (Hash Map)
An `unordered_map` provides O(1) average-case retrieval for the most-accessed credentials, complementing the sorted tree structure.

### 🕸️ Breach Propagation Graph
A directed **graph** (adjacency list) models relationships between sites that share credentials. If a breach is detected on one node, a **BFS/DFS traversal** identifies all potentially compromised accounts.

### 🔢 Security Analytics
- **Password strength scoring** — entropy calculation via character set analysis and bit manipulation
- **Duplicate detection** — hash-based collision detection across the vault
- **Breach simulation** — graph traversal reports propagation distance from the compromised node
- **Custom SHA-256** — lightweight hash function for credential fingerprinting without external dependencies

### 💾 Persistence Layer
All vault data is written to structured binary files using `fstream`. Encryption keys are derived from a master password using a custom key-stretching function.

### ↩️ Undo/Redo (Stack)
All vault modifications (add/delete/update) push actions onto a `stack<VaultAction>`, enabling multi-level undo without external libraries.
