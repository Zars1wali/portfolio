## Security Architecture & Overview

The Cybersecurity Incident Management System (CIMS) is an enterprise-grade platform designed to streamline security incident response, threat containment, and vulnerability management. Built on PostgreSQL with custom PL/pgSQL triggers, the system enforces strict audit trails, rate limiting, and Role-Based Access Control (RBAC) at the database layer.

---

## Core Security Features

* **Role-Based Access Control (RBAC)**: Fine-grained permissions isolating Analysts, Incident Commanders, and Administrators.
* **Automated Remediation Triggers**: Database-level PL/pgSQL procedures that automatically elevate severity scores and lock compromised asset records upon critical threat detection.
* **Audit Logging & Tamper Resistance**: Append-only audit logs tracking all user queries, status transitions, and credential modifications.
* **API Protection**: Express gateway with API rate limiting, JWT token validation, and sanitized PostgreSQL queries protecting against SQL injection.

```sql
-- PL/pgSQL Trigger: Auto-elevate Incident Severity on Critical Threat Match
CREATE OR REPLACE FUNCTION elevate_incident_severity()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.threat_vector = 'CRITICAL_EXPLOIT' AND NEW.affected_assets_count > 5 THEN
        NEW.severity := 'CRITICAL';
        NEW.escalated_at := NOW();
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

---

## Architecture Breakdown

1. **Frontend / API Gateway**: Node.js & Express API with middleware enforcement (`authenticate`, `apiRateLimiter`).
2. **Database Engine**: PostgreSQL with custom schema design, indexes on high-frequency triage columns, and materialized views for security analytics.
3. **Containerized Deployment**: Multi-container Docker Compose setup for consistent deployment across staging and production environments.
